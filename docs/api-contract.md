# Personalization contract

Frontend remains vanilla ES modules and the original six-step UI. Backend is Node 24 HTTP with sharp for image validation. No mocked success or preset fallback is permitted in production. All image URLs are durable, same-origin, cookie-session-scoped `/api/assets/:id` URLs. Missing AI configuration returns `503 AI_NOT_CONFIGURED`.

USER COST CONSTRAINT: No paid AI calls are authorized. `CHARCOAL_ENABLE_PAID_AI=false` is the default even with an API key. Server and provider both enforce `paidRequestsEnabled:false` before any vision/image call; return `403 AI_PAID_DISABLED` without contacting OpenAI. Health/session report `paidRequestsEnabled` separately from credentials. Never enable via a web endpoint, auto fallback, setup script or saved configuration. Tests may explicitly enable an injected mocked provider/transport only. Future activation requires explaining the expected USD cost and obtaining explicit user approval. Current live AI remains disabled.

`GET /api/health` → `{ok:true, aiConfigured:boolean, visionModel, imageModel}`.

`GET /api/session` → `{state: object|null, cat: Cat|null, aiConfigured:boolean}`. `PUT /api/session` accepts `{state:object}` and persists UI state. `DELETE /api/session` clears current design/active cat (does not delete other sessions).

`POST /api/cats` accepts `{photos:[{name,mimeType,data}]}` with base64 encoded image bytes (1–3). Returns `Cat = {id, revision:1, photos:[{id,url,name,width,height}], traits:null|Traits}`. Replaces active cat and invalidates old jobs for rendering. `GET /api/assets/:id` is scoped to the requesting session.

`POST /api/cats/:id/analyze` accepts `{}` → `{catId, revision, traits}`. Traits match the original frontend shape: `pattern`, `coat`, `colors:{main,second,third}`, `eye`, `expression`, `face`, `ears`, `markings`, `distinctive`, `uncertain`, `summary`. Reject non-cat/invalid responses, do not fill an empty AI reply as a successful default cat.

`POST /api/generations` accepts `{catId, revision, mode:'real'|'art', traits, personality:{name,habits,favoriteToy,note}, regenerateCharmId?:string}`. Requires active cat and matching revision. Returns `202 {jobId}`. `GET /api/generations/:jobId` → `{id,catId,revision,mode,status:'queued'|'running'|'complete'|'failed'|'cancelled',progress:{completed,total,label},result?:Generation,error?:{code,message}}`. `DELETE /api/generations/:jobId` cancels. Generation should use the uploaded photo bytes and a shared generated identity reference; mode controls material and style. Regenerating one charm returns a result with the other charms preserved. No automatic costly retries.

`Generation = {id,catId,revision,mode,character:Asset,texture:Asset,charms:[{id,kind,title,why,material,asset:Asset}],createdAt,model}`. Asset `{id,url,width,height}`. Charms are generated face, full-body/personality pose, sleeping, and favorite toy; use at most four for the initial workflow. A generated canonical cat identity can be reused between modes for the same photo/profile signature. `regenerateCharmId` identifies a charm in the last result for this cat/mode. Provider failures mark the job failed, never return library artwork.

Backend provider module `server/openai.js` exports `createOpenAIProvider({apiKey, visionModel='gpt-4.1-mini', imageModel='gpt-image-1.5', fetchImpl=globalThis.fetch})` with `analyze(photos,{signal}={})`, `generate({photos,traits,personality,mode,kind,identity,signal})`, and `models`. Photos `{bytes:Buffer,mimeType,name}`. `identity` is an optional `{bytes,mimeType}` previously generated image. Kind is `identity`, `texture`, `face`, `body`, `sleep`, or `toy`. `generate` returns `{bytes:Buffer,mimeType:'image/png'}`. API failures have `code`, `status`, and safe message. Never log or return credentials/provider raw bodies. All generation calls use actual image multipart parts through `/v1/images/edits`.

Renderer module `frontend/src/rendering.js` exports `renderPersonalizedShoe({view,design,generation,clogColor=null}) -> Promise<HTMLCanvasElement>` and optional pure helpers. Views: `side`, `top`, `back`, `bottom`, `detail` (`close` aliases side/detail). Design uses original shape: `{upperOn,strapOn,strapStyle,direction,colors,accent,charms:[generatedCharmIds],...}`. Generated texture/charms use above Generation. Renderer locks original cream footwear silhouette/sole and masks only removable upper/strap; every view consumes the same generation, with genuine bottom from `a/g-soles.webp`. No family/example cat template used for actual personalized results. Preserve original asset geometry. Original side/top/back images and map/UV assets are in frontend/a.

Frontend API module `frontend/src/api.js` exports `api` with `health()`, `session()`, `saveSession(state)`, `clearSession()`, `uploadCat(files)`, `analyzeCat(catId,{signal}={})`, `startGeneration(request)`, `job(id,{signal}={})`, `cancelJob(id)`. All return parsed server payloads; errors have `code`, `status`, human `message`. No fake API success. `uploadCat` converts File/Blob inputs to base64 and respects limits. Generic `pollGeneration(jobId,{signal,onProgress})` resolves result only on complete, throws failed/cancelled. Optional browser-native `downloadFile` helper.

UI persistence excludes `blob`, temporary URLs, busy flags; stores profile, confirmed edits, active cat ID/revision/photo metadata, per-mode Generation results, selected generated charm IDs, current design and step. Backend disk state survives server restarts if DATA_DIR persists. Browser session cookie is HttpOnly/SameSite. Track cat ID plus request/version token in frontend so old completions never overwrite new cats or newer edits.
